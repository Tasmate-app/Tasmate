# Game UI Design

## 基本方針
- 本プロジェクトは一般的な業務用Webアプリではなく、ブラウザ内で動作するゲームとして設計する。
- 明るくポップで親しみやすいアニメゲーム風UIを基本とし、白・淡いブルーを基調にシアンや鮮やかなブルーをアクセントにする。
- ブルーアーカイブなど既存作品は雰囲気や情報設計の参考にとどめ、画面構成・ロゴ・固有アイコン・装飾・素材を複製しない。
- Material Design 3の考え方は、アクセシビリティ、状態表示、コンポーネントの一貫性に活用する。業務用ダッシュボードの見た目をそのまま採用しない。
- 装飾や演出よりも、タスク登録、タイマー操作、報酬確認などの使いやすさを優先する。

## 画面設計
- ホーム画面では3Dシェアハウスを主役にし、家具や施設とインタラクションできる空間にする。
- 全画面を共通のゲームUIフレームで統一し、通貨・素材・通知・ナビゲーションをHUDとして扱う。
- タスク管理、探索、育成、施設管理はゲーム内の画面やパネルとして表現する。
- サイドバー、業務用ダッシュボード、カード一覧をデフォルトの画面構成にしない。
- キャラクターステータス画面では、立ち絵または3Dモデルを主役にし、レベル・経験値・属性・能力値・特性・育成操作を整理する。
- キャラクター切り替えや詳細情報のタブを設け、概要と詳細を適切に分ける。

## デザインシステム
- 色、余白、角丸、文字サイズ、影、アニメーション時間をデザイントークンとして管理する。
- ボタン、タブ、バッジ、ダイアログ、ツールチップは共通コンポーネントを優先する。
- 画面ごとの表現を変えても、色・アイコン・文字のルールは共通化する。
- デスクトップを優先しつつレスポンシブ対応し、重要な操作を画面サイズに関係なく利用可能にする。

## 実装時の確認
1. 既存画面と共通コンポーネントを確認する。
2. 既存のデザイン規則・トークンを再利用する。
3. ゲームらしさと操作の分かりやすさを両立する。
4. 見た目だけでなく、実際の操作・状態変化まで実装する。
