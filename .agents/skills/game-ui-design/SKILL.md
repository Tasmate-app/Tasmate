# Game UI Design

## 基本方針
- 本プロジェクトは一般的な業務用Webアプリではなく、WebとNativeで動作するゲームとして設計する。
- 明るくポップで親しみやすいアニメゲーム風UIを基本とし、現行の白・淡いブルー・シアンを基調にした配色を維持する。
- ブルーアーカイブなど既存作品は雰囲気や情報設計の参考にとどめ、画面構成・ロゴ・固有アイコン・装飾・素材を複製しない。
- Material Design 3の考え方は、アクセシビリティ、状態表示、コンポーネントの一貫性に活用する。業務用ダッシュボードの見た目をそのまま採用しない。
- 装飾や演出よりも、タスク登録、タイマー操作、報酬確認などの使いやすさを優先する。
- モバイル基準のトークンをWebにも適用し、画面サイズに応じてレイアウトを調整する。

## デザインシステム
- 色、余白、角丸、文字サイズ、影、モーションは `packages/design-tokens/` を正とする。画面ごとに直値を増やさない。
- Nativeは `apps/mobile/src/theme/tokens.ts` の再エクスポートを使う。
- ボタン、タブ、バッジ、ダイアログ、ツールチップ、空状態、エラー表示は共通コンポーネントを優先する。
- 画面ごとの表現を変えても、色・アイコン・文字・操作のルールは共通化する。
- 既存の `src/components/ui/`、`src/components/game/`、`apps/mobile/src/ui/`、`apps/mobile/src/components/` を確認してから新規作成する。

## 画面構成
- 全画面を共通のゲームUIフレームで統一し、通貨・素材・通知・ナビゲーションをHUDとして扱う。
- Webは768px未満でHUDのメニューから開くドロワー、768px以上で常設の左サイドバーを使う現行構成を維持する。表示順と並び順は設定画面の「サイドバー」で変更できる。
- Nativeはタブ・スタック・ドロワーをExpo Routerの構成に合わせ、Safe Areaとタッチ領域を確保する。
- タスク管理、探索、育成、施設管理はゲーム内の画面やパネルとして表現する。
- キャラクターステータス画面では、立ち絵または3Dモデルを主役にし、レベル・経験値・属性・能力値・特性・育成操作を整理する。
- キャラクター切り替えや詳細情報のタブを設け、概要と詳細を適切に分ける。

## WebとNativeの違い
- Web固有のCSS、ホバー、キーボード操作と、Native固有のタッチ、Safe Area、スクロール、戻る操作を混同しない。
- Nativeの見た目・HIG・ネイティブコントロールは `expo-native-ui` を併用する。
- 画面遷移・タブ・モーダルは `expo-router` を併用する。
- 同じ機能でも、画面サイズや入力手段に応じて情報量と操作を調整する。

## 実装時の確認
1. 既存画面と共通コンポーネント、デザイントークンを確認する。
2. ゲームらしさと操作の分かりやすさを両立する。
3. 読み込み中・空・エラー・成功の状態を用意する。
4. キーボード操作、タッチ領域、コントラストを確認する。
5. 見た目だけでなく、実際の操作・状態変化まで実装する。
6. `README.md` の「画面」と `docs/01_project_overview.md` の画面構成に矛盾がないか確認する。
