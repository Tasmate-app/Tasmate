# 週間カレンダー・継続報酬の設計

タスクの予定を週単位で組み、1週間の達成率に応じて継続ランクと報酬倍率を更新する機能の仕様。
MVP はブラウザのローカルタイムゾーンと `localStorage` を前提とする。

## 1. 画面と導線

- `/calendar`：週間カレンダー、繰り返し予定、継続状況、週次判定履歴。
- 下部ナビの「計画」から開く。
- カレンダーの予定をクリックすると、その予定だけを編集・削除できる。
- 「毎週くり返す」で作成した予定は繰り返しルールとして管理し、ルール編集では今後の予定だけを更新する。
- 繰り返す曜日は個別選択に加えて「すべて」で月〜日を一括選択・解除できる。
- 週間の達成状況と報酬倍率はカレンダー上部に表示する。

## 2. 日付・週の扱い

- 日付キーはローカル日付の `YYYY-MM-DD`。
- 週は月曜 00:00 に始まり、翌週月曜 00:00 の直前で終わる。
- タイムゾーン設定はまだ持たず、実行環境のローカルタイムゾーンを使う。
- `scheduledAt` は既存互換のため ISO 日時で保持するが、週次判定は `scheduledDate` を優先する。
- 旧データに `scheduledDate` がない場合は `scheduledAt` からローカル日付を補完する。

## 3. タスクと繰り返し予定

### 個別予定

`Task` に以下を追加する。

| フィールド | 意味 |
|---|---|
| scheduledDate | 予定日（ローカル日付キー） |
| startTime / endTime | 同日の開始・終了時刻（任意、`HH:mm`） |
| recurrenceId | 生成元の繰り返しルール ID（任意） |
| archivedAt | 論理削除日時（任意） |

開始・終了時刻は両方指定するか、両方未指定にする。終了は開始より後でなければならない。

### 繰り返しルール

`RecurrenceRule` は曜日・時刻・適用期間を持ち、個別の `Task` を生成する。

- 対応頻度は週次のみ（`frequency: 'weekly'`）。
- `recurrenceId + scheduledDate` で重複生成を判定する。
- 削除済み（`archivedAt` あり）の予定も重複判定に含め、同じ予定を勝手に復活させない。
- アーカイブ理由は `archiveReason` に保持する。ユーザーが削除した予定は復元せず、ルール変更でアーカイブした予定だけを、対象曜日が再追加されたときに復元する。
- ルール変更時は、未完了かつ未アーカイブで当日以降の予定だけを更新・アーカイブする。
- 予定の日付を変更した場合は「その回だけ」の変更として扱い、元の予定日を `originalScheduledDate` に保持する。元の日の予定は再生成せず、ルール変更でも移動後の予定を上書きしない。
- 過去の完了記録と確定済みの週次判定は変更しない。
- アプリ起動時とカレンダー表示時に、対象週の予定を生成する。

## 4. 週間達成の判定

対象週のタスクから次を集計する。

- 対象タスク数
- 完了タスク数
- 達成率（完了数 / 対象数）
- 判定に含めたタスク ID

判定は次の順で行う。

1. 休息週なら `rest`。
2. 対象タスクが0件なら `pending`（100%扱いにしない）。
3. 完了数が対象数の80%以上なら `achieved`。
4. それ以外は `missed`。

必要完了数は切り上げ（5件なら4件、10件なら8件）。

### 対象タスクと削除の扱い

- 完了済みタスクは、削除されても対象数・完了数に残す。
- 未完了タスクは通常は対象に含める。
- 週の途中で作成され、同じ週のうちに削除された未完了タスクだけを対象から除外する。
- 以前から存在した未完了タスクを削除しても、分母からは消さない（達成率の水増し防止）。

## 5. 継続週数・ランク・倍率

- 達成：`currentStreak + 1`
- 未達成：`currentStreak - 1`（0未満にはしない）
- 判定保留・休息週：維持
- `totalSuccessfulWeeks` と `highestStreak` は未達成でも減らさない。

| 連続達成週数 | ランク | 報酬倍率 |
|---:|---|---:|
| 0〜1 | ルーキー | 1.00 |
| 2 | トラッカー | 1.10 |
| 3 | レンジャー | 1.20 |
| 4 | キャプテン | 1.30 |
| 5 | エース | 1.40 |
| 6 | マスター | 1.50 |
| 7 | グランドマスター | 1.60 |
| 8以上 | レジェンド | 1.75 |

倍率表・達成条件・週開始曜日は `src/domain/constants.ts` の `WEEKLY_RULES` に集約する。
UI や計算へ数値を直書きしない。

## 6. 休息週

- 現在週または来週を休息週に設定できる。
- 休息週は連続週数を維持し、達成・未達成のどちらにも数えない。
- 連続して設定できるのは2週まで。
- 判定済みの週は変更できない。
- 未達成によるペナルティを避けるための救済措置であり、乱用防止の詳細は今後検討する。

## 7. 報酬倍率の適用

- 倍率はタスク完了時の報酬だけに適用する。
- 初期設定では通貨・素材・経験値のすべてに適用する。
- 端数は切り捨てる。
- 施設生産やログイン報酬など、別系統の報酬には自動適用しない。
- `RewardRecord` に `baseReward` と `rewardMultiplier` を保存し、履歴で基本報酬と適用倍率を確認できる。
- 報酬確定は既存の `appliedRewardSessionIds` でセッション単位に冪等化する。

## 8. 週次判定の実行と冪等性

- アプリ起動時、タブ復帰時、定期実行時に未判定週を古い順に処理する。
- `lastEvaluatedWeekStart` の翌週から、直前の完了週までを対象にする。
- `WeeklyEvaluation.weekStart` は一意とし、同じ週を再判定しない。
- 遡及上限は `maxCatchUpWeeks`（260週）。
- 判定ルールを変更しても過去の解釈が変わらないよう、`ruleVersion` を履歴に保存する。
- 週次判定の時点で、その週の繰り返し予定を生成してから集計する。

## 9. データ

`AppState` に以下を追加する。

- `recurrenceRules: RecurrenceRule[]`
- `weeklyEvaluations: WeeklyEvaluation[]`
- `weeklyProgress: WeeklyProgress`
- `restWeeks: string[]`

`WeeklyProgress` は現在の連続週数・累計達成週数・最高連続週数・最終判定週を持つ。
倍率とランクは保存せず、`currentStreak` から算出する。

保存データのバージョンは 1 のまま、読み込み時に新規フィールドを補完する。
旧 `RewardRecord` は `rewardMultiplier = 1`、`baseReward = finalReward` として補完する。

`inventory`、`activeSession`、`weeklyProgress` などが欠損・不正な場合は初期値へ補完する。
`lastEvaluatedWeekStart` が不正な場合は未判定として扱い、週次判定を例外で止めない。
描画時の例外は `ErrorBoundary` で捕捉し、画面全体が白画面になるのを防ぐ。

## 10. サーバー化に向けた注意

現在の週次判定と報酬付与はクライアントで完結している。複数ユーザー・オンライン化では次が必要。

- サーバー時刻を基準にした週境界と判定
- ユーザー別の `userId` と認可
- 週次判定・報酬付与の一意制約
- クライアント改ざんを前提とした再検証
- タイムゾーン設定の保存と変更時の扱い
- 判定ルールのバージョン管理と移行

## 12. 未決定・制約

- ユーザー別タイムゾーン設定。
- 日跨ぎ予定（例：23:00〜翌01:00）は未対応。
- 同時刻に重なる予定の自動整列は未対応。
- 週の途中で繰り返しルールを停止した場合の厳密な達成率ルール。
- 休息週の回数制限・クールダウン。
- 祝日・長期休暇・試験週間などのカレンダー連携。
- サーバー側での報酬確定と監査ログ。
